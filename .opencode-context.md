# Mapa de Proyecto: Control de Equipos 3.0

## 1. Arquitectura
- **Patrón**: Monolito por capas con API REST + SPA
- **Frontend**: React 19 SPA con Vite 7, Tailwind v4, React Router v7
- **Backend**: Express 4 monolítico en `backend/`, sin separación por microservicios. Nodemon con hot-reload — el servidor se reinicia solo al editar cualquier archivo.
- **Base de datos**: SQLite local vía raw sqlite3 (`db/database.js`). Prisma completamente eliminado.
- **Comunicación**: HTTP/JSON + Socket.IO para notificaciones en tiempo real
- **External services**: Google Drive (backups), Nodemailer/Gmail (email), web-push (notificaciones PWA)
- **Auth**: JWT en httpOnly cookie + refresh token rotation

## 2. Stack Crítico
- **Node.js**: >=22.0.0
- **Backend**: Express ^4.18.2, sqlite3 ^5.1.7 (raw, driver único), JWT (jsonwebtoken + bcryptjs + zod), Socket.IO ^4.8.3
- **Frontend**: React ^19.2.0, Vite ^7.3.1, Tailwind CSS ^4.2.0, Framer Motion ^12.34.3, Recharts ^3.7.0
- **DB**: `sqlite3` ^5.1.7 (raw, driver único). Prisma eliminado completamente.
- **PWA**: Service Worker custom + offline fallback + manifest + push notifications vía web-push

## 3. Convenciones Detectadas
- **Backend**: CommonJS (`require`), estructura Routes → Controllers → Servicios → Repositorios
- **Frontend**: ESM (`import/export`), JSX sin TypeScript, lazy loading de páginas
- **Auth**: AuthContext de React (useAuth) en frontend, httpOnly cookie + refresh token rotation en backend
- **Nombrado**: Archivos backend en español (`equipos.controller.js`, `soporte.service.js`), variables en inglés
- **CSS**: Tailwind v4 con `@import "tailwindcss"`, glassmorphism, tema oscuro, indigo como color primario
- **Commits**: Conventional Commits desde sesión de remediación

## 4. Puntos de Dolor (Deuda Técnica)

### Alto Riesgo
1. **Dual DB access path**: ~~Resuelto. Prisma eliminado del proyecto (commit `aef2b15`).~~ Solo `db/database.js` como driver.
2. **Cero tests**: `"test": "echo \"No hay tests configurados\" && exit 0"`. Sin unit, integration, ni E2E.

### Medio Riesgo
3. **Sin Docker**: No hay `Dockerfile` ni `docker-compose.yml`. `iniciar_local.bat` es Windows-only.
4. **Sin CI/CD**: No hay workflows de GitHub Actions ni pipelines.
5. **Sin TypeScript**: Proyecto moderno (Vite 7, React 19, Prisma 6) pero todo en JS. Los `@types/react` en devDeps están sin usar.
6. **Sin logging estructurado**: `console.log`/`console.error` por todo el códigobase. No hay trace_id, ni pino/winston.
7. **Rate limiting parcial**: Solo `/api` general y `/api/auth/login` tienen rate limit.

### Bajo Riesgo
8. **Mezcla español/inglés**: Nombres de archivos y carpetas mezclan ambos idiomas.
9. **Node >=22**: Requisito muy reciente, posible incompatibilidad en CI runners antiguos.
10. **`.env.example` solo en backend/**: Scripts raíz dependen de vars de entorno no documentadas a nivel raíz.

## 6. Dominio y Propósito
Sistema institucional de gestión de inventario de equipos IT con:
- Ciclo de vida de equipos (alta, asignación, seguimiento, baja)
- Sistema de tickets de soporte con estimación de costos
- Inventario de repuestos con tracking de movimientos
- Gestión de préstamos de equipos
- IPAM (IP Address Management) con segmentación de red y VLANs
- Historial de asignación de personal
- Exportación a Excel, backups a Google Drive
- Sincronización multi-instancia con soporte offline
- Notificaciones push PWA + offline fallback
- Recuperación de contraseña vía email
