# Mapa de Proyecto: Control de Equipos 3.0

## 1. Arquitectura
- **Patrón**: Monolito por capas con API REST + SPA
- **Frontend**: React 19 SPA con Vite 7, Tailwind v4, React Router v7
- **Backend**: Express 4 monolítico en `backend/`, sin separación por microservicios
- **Base de datos**: SQLite (local/desarrollo) + PostgreSQL (producción/Railway), vía Prisma ORM + raw sqlite3
- **Comunicación**: HTTP/JSON + Socket.IO para notificaciones en tiempo real
- **External services**: Google Drive (backups), Nodemailer/Gmail (email), web-push (notificaciones PWA)

## 2. Stack Crítico
- **Node.js**: >=22.0.0
- **Backend**: Express ^4.18.2, Prisma ^6.19.2, JWT (jsonwebtoken + bcryptjs), Socket.IO ^4.8.3
- **Frontend**: React ^19.2.0, Vite ^7.3.1, Tailwind CSS ^4.2.0, Framer Motion ^12.34.3, Recharts ^3.7.0
- **DB dual**: `sqlite3` ^5.1.7 (raw) + `@prisma/client` ^6.19.2 (ORM)
- **PWA**: Service Worker custom + manifest + push notifications vía web-push

## 3. Convenciones Detectadas
- **Backend**: CommonJS (`require`), estructura Routes → Controllers → Servicios → Repositorios
- **Frontend**: ESM (`import/export`), JSX sin TypeScript, lazy loading de páginas
- **Nombrado**: Archivos backend en español (`equipos.controller.js`, `soporte.service.js`), variables en inglés
- **CSS**: Tailwind v4 con `@import "tailwindcss"`, glassmorphism, tema oscuro, indigo como color primario
- **Auth**: JWT en header `Authorization: Bearer`, dos guards: `verificarAutenticacion` y `verificarAdmin`
- **Commits**: Sin convención definida (no hay commits visibles)

## 4. Puntos de Dolor (Deuda Técnica)

### Alto Riesgo
1. **Dual DB access path**: `prismaClient.js` + `db/database.js` (raw sqlite3 con DDL propio). Riesgo de schema drift y comportamiento inconsistente.
2. **Cero tests**: `"test": "echo \"No hay tests configurados\" && exit 0"`. Sin unit, integration, ni E2E.
3. **Dev secrets hardcodeados**: `auth.middleware.js:17` fallback a `'dev-secret-key-change-me'`. `auth.controller.js` fallback a `'admin123'`.

### Medio Riesgo
4. **Sin Docker**: No hay `Dockerfile` ni `docker-compose.yml`. `iniciar_local.bat` es Windows-only.
5. **Sin CI/CD**: No hay workflows de GitHub Actions ni pipelines.
6. **Sin TypeScript**: Proyecto moderno (Vite 7, React 19, Prisma 6) pero todo en JS. Los `@types/react` en devDeps están sin usar.
7. **Dependencias duplicadas/muertas**: `sqlite` ^5.1.1 y `sqlite3` ^5.1.7 ambos instalados. `sqlite` parece no usarse.
8. **Dos modelos de soporte**: `soporte_tareas` y `tareas_soporte` coexisten, sugiriendo migración incompleta.
9. **Sin logging estructurado**: `console.log`/`console.error` por todo el códigobase. No hay trace_id, ni pino/winston.

### Bajo Riesgo
10. **Mezcla español/inglés**: Nombres de archivos y carpetas mezclan ambos idiomas.
11. **Node >=22**: Requisito muy reciente, posible incompatibilidad en CI runners antiguos.
12. **Rate limiting parcial**: Solo `/api` y `/api/login` tienen rate limit.
13. **`.env.example` solo en backend/**: Scripts raíz dependen de vars de entorno no documentadas a nivel raíz.

## 5. Dominio y Propósito
Sistema institucional de gestión de inventario de equipos IT con:
- Ciclo de vida de equipos (alta, asignación, seguimiento, baja)
- Sistema de tickets de soporte con estimación de costos
- Inventario de repuestos con tracking de movimientos
- Gestión de préstamos de equipos
- IPAM (IP Address Management) con segmentación de red y VLANs
- Historial de asignación de personal
- Exportación a Excel, backups a Google Drive
- Sincronización multi-instancia con soporte offline
- Notificaciones push PWA
- Recuperación de contraseña vía email
